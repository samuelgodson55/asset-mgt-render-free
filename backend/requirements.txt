# BUG FIX / PIN: every opentelemetry-instrumentation-* package above
# imports `pkg_resources` (to check installed-package versions against
# what it supports) the moment it's imported -- not only when
# OTEL_ENABLED=true actually calls `.instrument()`. `pkg_resources` used
# to ship inside `setuptools`, but setuptools>=81 dropped it entirely, and
# neither this app's Docker image (backend/Dockerfile's `python -m venv`)
# nor a bare `python -m venv` anywhere else bundles setuptools by default
# on modern Python -- so without this pin, a perfectly correct `pip
# install -r requirements.txt` can still produce a container that raises
# `ModuleNotFoundError: No module named 'pkg_resources'` the instant any
# api/*.py route that happens to import telemetry.py's lazy-imported
# instrumentors runs. Pinning below <81 keeps `pkg_resources` present and
# working; bump this once the opentelemetry-instrumentation-* packages
# above no longer need it (upstream is actively migrating away from it).
# NOTE: `pip-audit` (ci.yml's non-blocking scan step) will flag this pin
# against PYSEC-2026-3447 -- a MANIFEST.in exclusion bypass that only
# matters when BUILDING a source distribution (`python -m build --sdist`)
# on a normalization-preserving filesystem (macOS APFS/HFS+). This app
# never builds an sdist of anything, in Docker or otherwise -- irrelevant
# here, and the tradeoff (an unpinned/>=81 setuptools breaks
# pkg_resources outright, per this comment's own opening paragraph) isn't
# close.
setuptools<81
